# Goal prompt

The project-specific autonomous contract below must stay at or below 2,000 characters.

> Build the Online Shopping MVP in GOAL, SPEC, DESIGN, API, EPIC, ROADMAP, TASK, PROGRESS, PWA_I18N, and UI_SPEC. Seller auth and MYR products run locally; checkout and review remain. `sample/` is a separate business-rule reference: do not copy its code, UI, or demo credentials. Finish seller products, then public catalog/cart, guest multi-destination checkout, and seller order review. Keep both installable PWAs dependent on the backend API and SQLite database. The server owns authorization, prices, order numbers, immutable snapshots, idempotency, revisions, decisions, and audit. Use ignored server-side credentials; reject missing or weak production values. Keep real PII and secrets out of source, logs, and public artifacts. Support +60/+65 buyer and recipient phones and seven UI languages in the required order. Use bounded base64 seller images with private decoded storage. Offer explicit same-device phone/address history with typed or selected suggestions and clearing; no public lookup. MYR is the only currency. Collect destinations for seller review without shipping charges or delivery-area enforcement. Defer GST, payment, customer accounts/OTP, cross-device recovery, automatic messaging, and logistics. Record unresolved hosting, session, retention, and recovery decisions; ask only for material choices evidence cannot resolve. Loop: inspect rules/code/tests and TASK/PROGRESS -> choose highest-value unblocked task -> implement smallest complete slice -> run relevant API/data/build/browser/PWA/i18n/security checks -> self-review and independent review when useful -> fix valid findings -> update TASK/PROGRESS/contracts/README -> make one focused verified local commit -> repeat. Track Planned, Implemented, Verified, and Released separately. Never claim release from local tests. Preserve unrelated work; never push, open PR, merge, or publish without explicit request.
