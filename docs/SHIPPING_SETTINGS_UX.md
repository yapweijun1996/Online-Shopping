# Sender settings and scoped Company saves

Company settings has three groups sharing one existing API: General, Product page and Shipping. Saving submits only the active group: three General fields, three storefront text fields or eight sender fields. It uses the existing Owner-only, session/Origin/CSRF-protected PATCH `/api/v1/seller/company-settings`. Backend rules, schema, courier behavior and public shop exposure are unchanged.

## Layout and country entry

The Shipping card is titled Sender details and uses Contact and Address fieldsets. Contact name/phone and city/state use two columns on desktop and one on phones. Address lines span the available card width. Country uses localized names from the browser's `Intl.DisplayNames`, retaining the uppercase two-letter value. The selector lists meaningful named regions rather than every unassigned letter pair. A historical unknown value such as ZZ remains a code-only option. Other uppercase two-letter codes can still be entered using the explicit Other two-letter code control. Blank remains available. Switching away from custom entry disables the hidden custom input; locale refresh preserves the selected code and any custom draft.

All eight sender fields remain optional. Address line2 explicitly says optional. Phone remains a complete +60 or +65 phone number, not a phone-derived country selector. Existing backend `normalizeContactPhone` accepts valid MY/SG numbers, including valid fixed lines; the UI adds no mobile-only restriction. The backend normalizes the phone to stored digits, and the UI shows the canonical phone with its leading plus. A formatted raw input may use32 characters while normalized storage has a15-digit maximum.

The pure contract `public/shared/sender-fields.js` owns field limits and the distinct raw phone limit. `src/sender-settings.js` derives the existing senderFields shape while retaining database/export column order. Its migration and export consumers keep the same identifiers and limits. `Dockerfile.backend` explicitly packages this new shared dependency. `public/seller/sender-form.js` consumes the same contract without introducing DOM dependencies into backend validation.

## Save and draft behavior

Each shared group compares current values against its own canonical baseline. Reverting all values is a no-op. Shipping uses a localized Save sender details action and local dirty/saving/saved/error feedback. Save is disabled before a valid settings load, during a shared write and for unchanged values. A failed or malformed initial load cannot submit blank defaults. Retry is explicit.

A submit captures the active group's payload. Only that group's inputs are disabled while pending; sibling groups may still be edited, while a second shared write is blocked. Success validates the full existing response DTO, then hydrates and advances only the submitted group's canonical baseline. Sibling input values, dirty state and Cloud/AI drafts remain unchanged. Switching tabs does not change which group an in-flight request saves. A malformed success response preserves the draft and reports that the save could not be confirmed; it does not claim failure atomicity or fabricate success.

The shared Company form explicitly disables native whole-form constraint validation so inactive sibling drafts cannot gate the active group; backend validation and inline field feedback remain authoritative. Server validation preserves inputs, routes to the field's existing tab, associates a localized inline error via aria-invalid/aria-describedby and focuses the field after pending controls unlock. Correcting the affected field removes its stale error. Permission errors disable writes and offer a settings retry; unauthorized responses use existing login cleanup. Page/session identity and request sequence checks discard detached results. Company disposal also retains the existing Cloud/QR lifecycle cleanup. Unsaved shared-form drafts and local progress are not persisted outside the current page.

## Verification and limits

Baseline screenshots showed eight ungrouped controls and a raw country text input. Local real-app browser tests cover390/768/1280/1920px, OS light/dark preferences and the warm-plum light palette; OS dark does not establish an actual dark theme. English/Chinese desktop/phone screenshots are external artifacts. The browser tests exercise real partial PATCHes and canonical reloads, sibling isolation in both directions, reverted/no-op fields, optional clearing, historical ZZ and new AA codes, seven locale refreshes, keyboard focus and no horizontal overflow. Explicit fault injection covers initial503/malformed data, held duplicate writes, malformed PATCH responses,403/401, preserved drafts and detached results. A separate Categories edit/save/locale regression protects the other caller in the shared settings module.

Focused contract/export/API tests preserve optional values, phone normalization, field order and existing server rules. Cloud, QR, AI and PWA checks cover affected lifecycle/cache boundaries. The full root test suite is not run. These disposable local checks do not establish authenticated live production acceptance or courier integration; deployment identity and any owner-session acceptance are reported separately by the release owner.
