# Seller and Customer Portal UI/UX redesign

Date: 2026-09-28–29 (Asia/Singapore). Source of truth for this continuing image-led improvement pass. The running application and browser tests decide whether an anchor works; SVG proposals are illustrations.

## Requested outcome

Review the current Seller and Customer portals end to end. For each weak page, capture the real mobile/tablet/desktop baseline, ask Codex CLI `gpt-6-luna` to produce separate visual anchors in `ui/`, inspect and revise them, implement one coherent page/workflow at a time, and compare real after screenshots. Preserve data/API behavior, seven-language UI, keyboard use, and truthful Demo/Production wording. The Seller product editor must become a dedicated product page, so editing one product does not expose the rest of the catalog below the form.

The user's direct request authorizes implementation after a suitable design review. The KB-MCP `ui:visual-design-lifecycle` supplies page-archetype, hierarchy, responsive, accessibility, and truthful-data criteria; its owner-review stage is a design governance default and does not supersede this request.

## Acceptance gate per page

1. The page's primary job and action are clear; no invented counts, offers, payment, delivery, or runtime claims.
2. The anchor matches available data and existing business rules, with mobile/tablet/desktop composition and non-happy states specified.
3. Real browser screenshots after implementation show the intended hierarchy at the baseline sizes and no accidental horizontal overflow.
4. Relevant navigation, forms, loading/empty/error, keyboard/focus, localization, and state recovery pass in an isolated Demo; public Demo is read-only unless explicitly authorized for data writes.
5. Node syntax/tests and Worker dry run pass when frontend source or worker assets change. Documentation records what was tested and what remains unverified.

## Design reference notes

- [GOV.UK task grouping](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/) supports grouping related work and showing actionable status; adapt only where the Seller workflow has actual tasks.
- [Carbon status indicators](https://carbondesignsystem.com/patterns/status-indicator-pattern/) pair color with text/shape so status remains understandable.
- [NN/g dashboard overview](https://www.nngroup.com/articles/dashboards-preattentive/) favors essential information that can be scanned quickly. The Seller dashboard should show work to do rather than decorative charts or unavailable metrics.
