# Constructor-private CREATE adapter

The image-free version1 contract below remains unchanged. Finish-enabled unified creation uses a separate strict [version2 parent branch](UNIFIED-CREATE-PARENT.md) with draft-owned staged sources and one complete approval.

`catalogMediaCreateTool(runtime)` preserves the existing safe CREATE name, input schema and minimal receipt schema, substituting `catalogMediaCreateAdapter(runtime)`. It fixes `catalog/catalog` and the source-owned media marker. It is not registered or authorized here. The eventual CREATE profile requires its own separately reviewed gate; enabling the independent UPDATE profile must not authorize CREATE.

`runtime` supplies a fixed `codecDigest` and `nativeSession`. The engine will own the capture, lock-free resolve and final fenced preview phases. Capture normalizes the original safe input through the existing product normalizer, after only a bounded currency lookup, and allocates the strict server product/listing identity without writing ghost rows. Global metadata preflight and the shared full-settings preflight precede business-service text reads. The shared CREATE state/projector/assembler builds the complete review; native validation receives only the exact used old seven-field DB references, with no stage or upload-before-product flow.

Resolve calls the existing bounded native session outside both database locks. It returns verified source dimensions and the same context/request/identity/revisions. It neither selects a tenant nor authorizes a write. The final preview rechecks every source component and rebuilds the one shared manifest. Empty/private creation has no images to decode, but still produces a review page and remains HIGH with both required scopes in the future policy.

`parseCatalogMediaCreateProposal` accepts exactly `kind`, `normalizedInput`, `creationIdentity`, `before`, `after`, `optionReview`, `sourceRevision`, `reviewLabels`, `reviewBinding`, `media` and `warnings`, capped at 48 KiB. BEFORE is null; AFTER is actual adopted metadata with resolved options. The canonical request stays separate from the final derived label, including the existing 80-unit Unicode/space clipping behavior. Finite server-generated warning codes describe existing-listing field adoption and actual shared-gallery effects. Unrelated settings/contact text is bounded internally and never copied into the proposal.

`readCatalogMediaCreateReview(read, { normalizedInput, creationIdentity }, codecDigest, expectedSource?)` is the common private reader. Expected source revisions stop a raw catalog change before service normalization or a new target can be adopted. Physical changes also stale the pinned identity. `currentRevision` returns `{ exists: true, revision: null }` for changed intent/resource facts: the catalog root concept still exists. Only unchanged source may rebuild the same full review, including warnings. Database and size failures propagate.

Apply compares the complete fresh proposal and retained frame, then calls the real planned CREATE service through `trackCreate` and `withInventoryContext` with the actual seller/client/grant/operation/correlation identity. It performs no commerce SQL. The shared physical AFTER kernel checks all old bytes, references, thumbnails, layouts and views plus exact copy effects. Raw AFTER metadata verifies all old rows/stock/mappings/listings/dictionaries remain, permitting only the real holder layout and monotonic version change caused by sharing. New IDs, adopted fields/options, initial stock, actual strictly appended creation time, one initialized ledger movement and one history event are asserted before returning a result.

The receipt contains only `{ productId, listingId, revision }`. Revision binds actual post-creation raw facts plus the real new-product media closure; it is not the approved-before projection hash. Repeated direct apply stales on the occupied planned ID. Future engine COMMITTED replay must return its retained minimal receipt before invoking these callbacks or loading purged proposals/frames/resources.

Tests call this private component with actual disposable SQLite/PostgreSQL stores and an explicitly synthetic native decoder. Synthetic retained frames contain no approval/evidence rows. Simulated caller writer/audit/receipt failures demonstrate transaction rollback, not actual CREATE engine authorization or human approval. No native Docker, browser, runtime flag, registry, central authority or schema activation is part of this batch.
