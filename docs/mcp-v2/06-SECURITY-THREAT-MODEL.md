# Security threat model

Status: **Isolated implementation and final integrated acceptance complete.** [Progress](09-IMPLEMENTATION-PROGRESS.md) and [validation](10-FINAL-VALIDATION-REPORT.md) record source, commands, failures and limits. All32 tools, including full CREATE/UPDATE, now have component and genuine default OAuth/native/HTTPS workflow evidence. Cross-domain tests verify all24 new actual responses and per-name negative calls on both stores. Bounded independent source reviews found no confirmed P0/P1/P2; this is not exhaustive security certification. Hashes/synthetic frames never substitute for human authority. New write flags default off; production activation is rejected.

| Threat | Required control | Evidence required before enabling |
| --- | --- | --- |
| Prompt injection in product, notes, images, KB or MCP text | Treat all external text/media as data; render through safe text APIs; no model-supplied approval. | Injection fixture in protocol and approval browser flows; no new authority. |
| Cross-tenant or cross-product reference | Derive tenant/store from server router; validate every resource and staged media in that store; bind operation and grant. | Two-tenant and cross-product tests. |
| Approval forgery, replay or hash substitution | Fresh authenticated first-party seller UI, CSRF/origin, exact stored digest, short expiry, one-use transition. | Forged UI/tool args, altered hash, wrong session/identity, replay and race tests. |
| Revoked token/grant, disabled account or downgraded role | Revalidate current token, grant, audience, account, role and policy inside commit transaction; all writers must honor the existing store lock. | Synthetic separate-process PostgreSQL tests observe the lock while grant revoke, disable, downgrade and logout compete with a pending commit. A writer bypassing the app store lock is not protected by these tests; production operational privileges and multi-instance procedures remain release gates. |
| Shop suspended during an in-flight operation | Hold a verified platform lifecycle guard through the tenant transaction and bind lifecycle revision; never rely on the cached initial lookup. | Integrated two-database lifecycle/authority tests and actual application review routes are covered by the named foundation snapshot. Production coordinated multi-instance restore remains unverified. |
| Stale concurrent seller edit | Compare the full affected set and execute the shared service inside the same serialized transaction. `syncListing` can change sibling fields without their timestamps, so a target-only timestamp is insufficient. Real sharing copy/layout changes now monotonically advance the holder version, so an old Seller Gallery selection cannot delete the new copy; no-op sharing leaves it unchanged. | Complete SHA-based metadata/media revisions, stale service/HTTP gallery regressions and transaction rollback on both stores. Full UPDATE/CREATE concurrency matrices and the final2012/2012 integrated suite passed in isolation. |
| Idempotency collision or duplicate commit | Bind key to tenant/account/client and canonical intent; enforce unique constraint; replay only authorized same intent. | Concurrent same/different requests; side effect exactly once. |
| Upload parser abuse, excessive pixels or decompression | Bounded body and staging, validate actual bytes and fully decode under separately enforced native memory, dimensions and checksums; no paths/URLs. See [media delivery plan](MEDIA-DELIVERY-PLAN.md). | Format confusion, truncation, excessive dimensions/decoded size, stage expiry/rollback. Baseline only checks signatures. |
| Unauthorized information disclosure | Existing redacted projections; least-privilege new fields; bounded output; audit excludes personal text/secrets/media bytes. | Contract/redaction/response-cap and logs tests. |
| Race or infrastructure error between mutation and audit | One database transaction; fail closed; never acknowledge mutation without its audit. | Injected persistence/audit failure and two-adapter rollback. |
| Expensive requests, staging or queries | Strict schema/body, deadlines, pagination, indexes, rate limits, storage quotas, cleanup. | Negative size/rate tests and measured query plans/performance. |
| Knowledge service unavailable or malicious | KB is optional context, not the authority for live state or permission. | Deny writes without approval despite unavailable/malicious KB. |
| Restored or imported consent/approval becomes live again | Explicitly invalidate pending v2 authority on restore/import while retaining appropriate audit evidence. | SQLite-to-PostgreSQL synthetic import and coordinated-restore tests; no resurrected approval or write grant. |

P0 release blockers: any approval bypass, cross-tenant disclosure/write, lost edit, duplicate order decision, unaudited commit or privilege escalation. The implemented company path is available only under safe isolated opt-in and fresh consent. Media and other unaccepted domain paths remain unavailable. Source review and local tests are not external security certification.
