# Production MCP recovery gates

A runtime's external epoch is a restore domain, separate from its shop database. Mount the containing `/run/mcp-control` directory read-only into the backend; do not bind a single file inode. Keep the epoch outside database backups. An operator replaces its canonical 32-byte base64url contents atomically during coordinated restore or binary rollback. A running process checks the current pathname at its authorization fences and rejects changed, missing, malformed or unreadable values. It never adopts a replacement epoch. Restart the reviewed backend with the new configuration before reopening traffic; previous consent and operation approval do not transfer to the new epoch.

Block ingress and drain all writers before rotating the epoch, restoring data or changing an incompatible image. Filesystem replacement and a database commit are not a single atomic transaction; repeated authorization checks do not remove this operational requirement. Native resolution occurs outside database locks and is checked again in the final writer phase. Configured production activation requires `TRUST_PROXY=1` for the reviewed HTTPS gateway topology; Origin, CSRF, current grant/RBAC and individual approval remain mandatory.

Database restore also restores old password hashes and legacy credentials. Before reopening, revoke restored OAuth authority and seller sessions through the host-only recovery workflow, and require an out-of-band trusted owner password reset through the existing password-reset service. Epoch rotation alone and `mustChangePassword` alone do not satisfy that password-reset gate. Recovery must not fabricate a password approval, automatically choose new passwords or silently disable accounts. Binary rollback without database restoration requires a new epoch but does not require unrelated credential revocation or data undo.

All commands and orchestration described here require trusted operator authorization. This source checkpoint does not install a timer, change a mount, rotate production credentials or demonstrate live recovery. Code eligibility is not human approval or hardware attestation.
