# Private CREATE review assembler

The image-free version1 contract below remains unchanged. Finish-enabled unified creation uses a separate strict [version2 parent branch](UNIFIED-CREATE-PARENT.md) with draft-owned staged sources and one complete approval.

`buildCatalogCreateReviewManifest({ state, projection, codecDigest })` extends the same module and assembly path as [UPDATE](CATALOG-UPDATE-REVIEW-ASSEMBLER.md). Inputs are fresh private outputs from the SELECT-only CREATE reader/projector, including the canonical request and separately prepared values. The function has no database/writer, permission flags, model-selected tool or stage input. It fixes `catalog.preview_create` and returns `{ manifest, revision, reviewBinding }`.

The wrapper compares the unchanged shared D1a revision preimage, strict creation identity, final metadata/options, actual source union and complete before/after product membership. Existing target labels come from its real captured products. New labels come from the adopted final AFTER metadata. Real BEFORE views include only old products; no fake new-product BEFORE view is added. `EMPTY_BEFORE` supplies empty private resource metadata, explicitly not a fabricated database snapshot.

The existing `assemble`, product-state/visibility checks, ID union, exact seven-field old-source filter, shared conservative byte mapper and bounded review-binding record stream are reused. Physical copy and thumbnail costs must match the private after-byte count. Copy/layout actions are closed metadata and must belong to the actual old holder; no new UUID/body/stage alias is invented. Unused physical sources are excluded from the manifest; all used aliases must exist exactly in captured old DB resources and belong to a product present BEFORE. Source content limits and all graph/page caps remain in force.

Exactly one PRODUCT has null BEFORE and no own main AFTER; fresh/private creation also has a null-before LISTING. The full union includes the new IDs even when BEFORE is empty. A zero-asset result still emits two effects and at least one hash-bound review page. UPDATE's existing input/output and revision semantics remain unchanged; the separate CREATE revision domain binds the planned identity and the shared visible/label projection.

This pure wrapper is not an approval or authority check. The future runtime must hold its platform/tenant fence, recheck live original-grant authority and complete resource state, use the actual canonical-request D0 service atomically, and preserve minimal COMMITTED replay without loading purged state. The CREATE profile remains RESERVED; the separate UPDATE runtime gate does not enable CREATE. Actual safe null-marker CREATE contracts are unchanged.

Tests compare both-database real D0 AFTER ownership, ordered visibility, copied thumbnails, adopted metadata and options against assembled effects, exercise honest EMPTY and full10+own11 targets, roundtrip canonical SQL frame metadata, and reject mismatched requests/IDs/revisions/aliases/copy costs without writes. These are private business/integrity tests, not actual OAuth/browser CREATE approval evidence.
