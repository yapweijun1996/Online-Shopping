## 5. Known traps (each one has bitten or will bite)

1. `createApi` caches one route table per `tenant.id` with the store captured; a pool that evicts and closes an idle store leaves a handler pointing at a closed store (X19).
2. `sw-core.js` deletes every cache whose name starts with `<cachePrefix>-`, and its fetch handler ignores only paths that start with `/api/`. Both break as soon as two shops share an origin (X15).
3. `cookieFor` hard-codes `Path=/api/v1/seller` (`src/auth.js`).
4. Server-generated URLs are absolute: share previews (`origin + /shop/...`, the `enter` redirect, `url`, `image`), `/s/home`, `serveStatic` redirects (`/` to `/shop/`), manifests, the WhatsApp callback URL shown in the seller UI. They all need `<base>`.
5. In production Caddy, not Node, serves `public/`; `Dockerfile.backend` copies only a few `public/` files. Every `src/` import of a `public/` file must be copied there (`test/backend-image.test.js`), and new backend-run scripts must be added to its `COPY scripts/...` line.
6. `deploy/Caddyfile.production` separates the hosts: the shop host blocks seller paths, the seller host blocks buyer paths. Every prefixed variant needs the same blocks.
7. Rewriting the URL of a POST request must keep the streaming body (`duplex: 'half'`).
8. `Host` is trusted only because Caddy preserves the public hostname; the admin host check must compare the exact configured value.
9. Compose bind-mounts a missing secret file as an error: files first, compose reference second (X4). Values in `runtime.env` must be literal single lines without `$`.
10. The installed controller (`~/Library/Application Support/Online-Shopping/auto-deploy/auto-update.py`) does not update itself. `deploy/backup-postgres.py` runs from the **current** release checkout, so a new backup script takes effect only after the release that contains it is deployed.
11. `compose_violations` allows new services and new secrets but rejects any change to the `postgres` or `tunnel` service, to an existing secret, volume or network, host-path bind mounts outside the release, host namespaces, privileges and non-loopback ports. Check your compose diff against it (`python3 test/auto-update.test.py` and a rendered-config comparison).
12. `cloudflared tunnel route dns` must be given an explicit `--config` pointing at a throwaway file naming the right tunnel (see `docs/ORBSTACK_DEPLOY.md`); an unrelated default `~/.cloudflared/config.yml` can select the wrong tunnel.
13. PostgreSQL `max_connections` is 100. Budget every pool.
14. The P2 tests ran as a superuser and hide PostgreSQL 16's role-creation rules (X6).
15. The legacy shop must never depend on the platform: root paths and `/ready` never read the platform database (X3).
16. The numbers "69 API strings and 143 absolute references" in the older plan are stale. Re-count with the guard test (81 `/api/v1` hits in 18 files at the time of writing).

## 8. Autonomy protocol

- **Unknowns:** rule D0, ledger entry, continue.
- **Failing check:** diagnose, fix, rerun. At most five fix cycles per distinct failure; then record it, move to independent work, and come back once more. If it still fails, the run is `BLOCKED`.
- **Denied tool call or missing authority** (a permission prompt that is not granted, a sandbox or classifier denial, a missing credential, an action class your launch message does not cover): do not retry the same call and do not look for another route to the same effect. Write a ledger entry `BLOCKED: <purpose>` with the exact command and what depends on it, continue every step that does not depend on it, and list it in the handoff file under "Needs the owner" with the command to paste.
- **Production stop conditions:** if `/ready` on either public host fails twice in a row after a deploy and the updater has not rolled back, revert the merge first (rollback in section 7) and investigate afterwards. If the load or memory of the host threatens other services, stop heavy work, wait, and resume serially.
- **Concurrency:** one deploy in flight at a time; never edit the updater's state by hand; never delete release checkouts, images or backups.
- **Independence:** use a separate reviewer for MT-17 when tools allow. Do not mark an item done on your own test of your own code without also running it through the real stack named in the item.
- **Commits:** small, verified, English messages, one purpose each; do not commit `.local/`, `output/`, secrets or databases; the repository's attribution convention for commits and pull requests applies.
