# Seller category codes: image-led review

The baseline is the real local Demo at [desktop](seller-v73-audit-categories-1440.png), [tablet](seller-v73-audit-categories-820.png), and [phone](seller-v67-before-categories-mobile.png). The 820 px baseline made the six category rows unnecessarily tall and previously split immutable codes. Codex CLI `gpt-6-luna` generated the first [desktop](seller-v68-categories-proposal-desktop.svg), [tablet](seller-v68-categories-proposal-tablet.svg), and [phone](seller-v68-categories-proposal-mobile.svg) anchors. Their SVG canvases were transparent and rendered with black empty regions; the tablet controls were also smaller than the stated 44 px target. They were rejected as implementation references.

Luna regenerated [desktop](seller-v71-categories-proposal-desktop.svg), [tablet](seller-v71-categories-proposal-tablet.svg), and [phone](seller-v71-categories-proposal-mobile.svg) anchors with a full background and touch-sized controls. The tablet row structure is useful: keep the fixed code on its own line, then put the editable name, availability, and per-row Save on one line. The regenerated desktop and phone illustrations still have incomplete top-bar geometry, so the existing live shell remains authoritative. The phone keeps its existing vertical category card.

The local implementation applies the tablet row structure at 761–900 px through the existing responsive CSS. Real [desktop](seller-v72-after-categories-desktop.png), [tablet](seller-v72-after-categories-tablet.png), [phone](seller-v72-after-categories-mobile.png), and [Thai 761 px](seller-v72-after-categories-tablet-th.png) captures provide the after comparison. At 320, 390, 761, 820, 900, and 1440 px there is no horizontal overflow or code splitting. Seven locales at 320, 390, 761, 820, and 900 px showed no row-control overlaps, and Save stayed 44 px high. The 820 px keyboard order remains display name → availability → Save. Category create, rename, and deactivate had already passed on the isolated Demo; this CSS change does not alter their behavior.

The visual anchors are design references, not screenshots of the implemented page. Their illustrative category data is synthetic and does not define the data contract.
